# Локализация консоли TAO (zh-CN → ru/en)

Исходный язык интерфейса — китайский. Перевод живёт **отдельным словарём**, `app.js` не переписан.
Устройство рантайма — `docs/I18N.md`, здесь только рабочий цикл.

## Пайплайн

```bash
python3 tools/i18n_extract.py     # раунд 1: литералы app.js/index.src.html + backend-строки
python3 tools/i18n_extract2.py    # раунд 2: ast для python + HTML из шаблонов app.js (то, что пропустил раунд 1)
# -> tools/i18n_src.json, tools/i18n_round2.json, батчи в tools/i18n_batches{,2}/
# ... перевод в tools/i18n_out{,2}/batchNN.json ...
python3 tools/i18n_validate.py    # id, пустые значения, %s, остатки CJK
python3 tools/i18n_build.py       # -> tam/web/i18n.data.js (плюс tools/i18n_extra.json поверх)
cd tam/web && python3 build.py    # -> tam/web/index.html
systemctl --user restart tgcrm
```

## Формат батча

Вход `[{"id","kind","zh"}]`, выход `{"<id>": {"ru": "...", "en": "..."}}` — ровно те же id.

| kind | что это | правило |
|------|---------|---------|
| `frontend` | строки из `app.js` / `index.src.html` | переводить текст, HTML-теги/`onclick` не трогать |
| `pattern` | шаблон с `%s` (`${...}` в JS) | столько же `%s` в том же порядке |
| `backend` | описания инструментов/параметров, ошибки API | переводить текст вокруг `{expr}`, регулярки и код не трогать |

## Грабли (проверено на 11 + 4 батчах)

- **Регулярки** в `backend` (`(?im)(?:CNY|人民币|RMB)…`) не ломать: синтаксис и группы сохранять,
  китайские альтернативы заменять (`人民币`→`юань`/`yuan`, `[a-z秒分时天]`→`[a-zа-я]`/`[a-z]`),
  после записи прогнать `re.compile` на обоих языках.
- **f-строки**: переводить только китайские литералы внутри `{...}`, само выражение — байт-в-байт.
- **Сепараторы** ` · `, ` | `, `/`, `→`, `【】` сохранять; `：` в середине → `: `, в конце строки → `: `
  (пробел нужен: рантайм отдаёт значение как есть).
- **Фрагменты склеек** (`后`, `天`, `小时`, `将删除选中的`, `向「`) переводить под склейку, но **без**
  ведущих/хвостовых пробелов: пробел уже стоит в соседнем куске, а рантайм сохраняет пробелы узла.
  Исключение: если склейка идёт через `<strong>`/`<code>`, пробел ставит сам `i18n.js` (см. ниже).
- **Страны** хранятся как `加纳 \ud83c\uddec\ud83c\udded` — хвост это литеральные `\uXXXX`. Хвост
  копировать как есть, переводить только название; сборщик сам декодирует эскейпы в настоящие эмодзи
  и затем вырезает флаги (на машинах без emoji-шрифта они дают «тофу»).
- **Системные промпты** AI (`你是…助手。…简体中文`) — это инструкция языка ответа: переводить как
  `Отвечай по-русски…` / `Answer in English…`.
- Не индексировать JSON в RAG (`library_add` берёт только md/txt) — индексировать `docs/I18N.md` и скилы.
- `i18n_build.py` печатает `missing ids` — это про ещё не переведённые батчи, а не про ваш.

## Ручные правки словаря

`tools/i18n_extra.json` — `{"<zh>": {"ru","en"}}`, применяется **последним** (перекрывает батчи).
Ключ с `%s` становится шаблоном. Так правят: неудачные переводы, строки, которых не было в исходниках,
динамические сообщения (`"%s 分钟后"`, `"隐藏【%s】"`), контекстные омонимы (`分钟`→`мин`).

## Рантайм: что важно знать переводчику (`tam/web/i18n.js`)

1. Поиск: точное совпадение → шаблон `%s` (длинные шаблоны первыми) → разбиение по ` · `.
2. Захваченные группы переводятся **рекурсивно**: `5 分钟后` → `%s 分钟后` → `%s 分钟` → `5 мин`.
3. На границе с `<strong>/<code>` пробел добавляется автоматически (китайский пробелов не ставит).
4. Одиночная китайская пунктуация (`、。，：；（）「」【】`) маппится в латинскую/`«»`.
5. Непереведённая строка остаётся китайской — безопасный фолбэк, но это баг, который надо добить.

## Критерий «получилось»

```bash
python3 tools/i18n_validate.py     # все батчи OK
python3 tools/i18n_build.py        # без "missing ids"
```
И в браузере: переключить RU/EN, пройтись по всем модалкам/панелям, выполнить сниппет из
`docs/I18N.md` — должно вернуть `0`.
