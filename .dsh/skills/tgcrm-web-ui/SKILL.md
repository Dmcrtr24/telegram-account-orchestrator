# Новый экран в веб-консоли TAO (tgcrm)

## Где что лежит

| Файл | Роль |
|------|------|
| `tam/web/index.src.html` | разметка (исходник) |
| `tam/web/styles.css` | стили (исходник) |
| `tam/web/app.js` | вся логика (~10k строк, один классический скрипт) |
| `tam/web/i18n.data.js` | **генерируемый** словарь, руками не править |
| `tam/web/index.html`, `index.min.html`, `release/*` | **сборка** `build.py`, руками не править |

Сборка и перезапуск (обязательно оба шага, иначе сервер отдаст старое):

```bash
cd tam/web && ../../.venv/bin/python build.py && ../../.venv/bin/python build.py --release
cd /home/golden/Проекты/tgcrm && systemctl --user restart tgcrm && curl -s -o /dev/null -w '%{http_code}\n' localhost:8848
```

## Зарегистрировать вид (5 мест, иначе пункт меню «мертвый»)

1. `const VIEW_NAMES = {...}` в `app.js` — **без записи здесь `switchView()` молча выходит**
   (`if (!VIEW_NAMES[view]) return;`). Симптом: кнопка в меню есть, клик ничего не делает.
2. Разметка: `<div class="card pane ..." data-widget="x" data-view="x">` внутри `.board`;
   `applyView()` сам скрывает/показывает по `data-view`.
3. Кнопки навигации: `data-nav="x" data-onclick="switchView('x')"` — в `.pillnav` (десктоп)
   и, если раздел основной, в `.tabbar` (мобильный, иконка из SVG-спрайта `#i-*`).
4. `switchView()`: ветка загрузки данных вида (`if (view === 'x') loadX();`) — вид не грузит
   данные сам по себе, только через этот хук.
5. `applyView()`: класс на `<body>` (`document.body.classList.toggle('x-workspace', ...)`),
   если виду нужен особый скролл/высота (например `overflow:hidden` у `.content`).

## CSP-обработчики: только 4 события

`data-on*` переплетаются интерпретатором с белым списком **click / change / input / load**
(`const TYPES` в `app.js`). `data-onkeydown` не существует — Enter/стрелки вешать
`addEventListener` в JS. Внутри `data-onclick` разрешены вызовы, литералы, `this`, `event`,
присваивания и стрелки; верхнеуровневые `const/let` доступны через авто-мост
(`build.py` сканирует объявления и генерирует `__taoLexHas/__taoLexGet/__taoLexSet`).
Функции-декларации доступны и так.

## Данные: типовой цикл вида

```js
function xOnView() { /* выбрать аккаунт/объект, отрисовать список, вызвать загрузку */ }
async function xReload() { const seq = ++X.seq; /* api(...) */ if (seq !== X.seq) return; /* рендер */ }
```

* `api(path, {method, body})` — обёртка fetch с токеном и разбором ошибок; кидает `Error`
  с уже локализованным текстом.
* Любой асинхронный ответ проверяй по счётчику (`seq`), иначе переключение объекта даёт
  «прилипшие» данные прошлого.
* Состояние выбора храни в `localStorage` (`tam.chatAcc`), чтобы после перезагрузки
  открывалось то же самое.
* Вход из строки/карточки аккаунта: функция вида `openX(id)` → `closeAll()` + `switchView('x')`,
  а id передавай через поле-«хотелку» (`X.want`), которое вид забирает в `xOnView()`.

## Локализация

Строки в исходниках — **по-китайски**, русского в `app.js` быть не должно (иначе в EN останется
русский). Новые строки: добавить в `tools/i18n_extra.json` (`{"<zh>": {"ru": ..., "en": ...}}`),
для шаблонов использовать `%s`, затем `python3 tools/i18n_build.py` и пересборка.
Динамические префиксы тостов переводить через `tamI18n.t(...)` — текстовый узел целиком
не совпадёт со словарём.

## Проверка «получилось»

1. `curl -s -o /dev/null -w '%{http_code}' localhost:8848` → 200, `systemctl --user is-active tgcrm` → active.
2. Открыть раздел, проверить в консоли браузера, что нет ошибок JS (кроме ожидаемых 4xx от API).
3. Остатки китайского — сниппет из `docs/I18N.md` (обход текстовых узлов + `placeholder/title/aria-label`).
4. Данных может не быть (мёртвые сессии) — тогда проверять на фейках: в **обычном** режиме
   подменить `window.fetch` (`?demo=1` не годится: `api()` уходит в `demoApi` и мок не сработает):

```js
window.fetch = async (u, o) => String(u).includes('/dialogs')
  ? new Response(JSON.stringify([{id: 1, name: 'Тест', unread: 2, is_group: false, date: Date.now()/1000 - 300, preview: 'привет'}]), {status: 200})
  : orig(u, o);
```

5. Мобильная вёрстка: `page.setViewportSize({width: 430, height: 880})` — колонки должны
   складываться в шаги, а не обрезаться.

## Грабли

* `index.html` — сборка. Правка в нём «работает» до следующего `build.py` и теряется.
* Светлый/зелёный кружок, плывущий за курсором на скриншотах — это декоративный `fx-cursor`,
  а не баг вёрстки.
* `.content` по умолчанию скроллится; для экрана на всю высоту нужен `body.<view>-workspace .content{overflow:hidden}`
  + `flex:1;min-height:0` у панели, иначе двойной скролл и обрезанное поле ввода.
* `build.py` печатает предупреждение про `sys.prefix` при запуске через `../../.venv/bin/python` —
  безвредно.
* После `git`-правок фронта появляются новые хешированные файлы в `tam/web/release/` — старые
  надо удалять (`git rm`), иначе репозиторий пухнет.
